This page runs a JavaScript port of the model in 04-binmonjil-chandy-lamport/exp1/solution.lisp (the experiment-1 solution). Functions and fields use the ACL2 names. The abstract application and topology (the encapsulate) are given the same concrete functions as the reviewer's evaluation script reviews/04-binmonjil-chandy-lamport-exp1-eval.lsp.

4. Why pre and post steps commute

Sort e by repeatedly swapping an adjacent pair x; y where x is postrecording and y is prerecording (an "inversion"). Each swap is checked by actually running both orders: from the state S before the pair, (cl-run S (list x y)) and (cl-run S (list y x)) must be equal. If they are, the rest of the run is unchanged, so the final state is unchanged. When no inversions remain, the sequence is (append pre post).

5. The topology is unconstrained: why the theorem still holds

The topology functions in-nbrs, out-nbrs and sys-procs are declared in the solution's encapsulate with no constraints at all. The only constraint there is app-make-msg-not-marker. The authors' model is stricter: its good-state-p requires unique process ids (uniquep) and incoming/outgoing lists that agree (nbrs-from-to-consistent-p, nbrs-to-from-consistent-p).

Because MAIN is proved about the unconstrained functions, it holds for every topology, including ones the authors would reject. The proof doesn't need consistency because:

  • Swaps need only different processes and FIFO channels. The commuting argument in section 4 looks at the two processes of the swapped inputs and at the channel between them. It never uses :in lists matching :out lists, or ids being unique. A channel that nobody can receive from is only ever appended to, and appends at the tail commute with everything.
  • The marker invariant cl-inv only talks about :out. It says: if q has recorded sid, p has not, and p is in (outs-of q s), then sid's marker is on channel (q . p). Every step preserves this in any topology, because recording always sends the marker on every outgoing channel.
  • Inconsistency can only make segments fail to complete. If a process waits for a marker that can never arrive (from a non-process, or on a channel it cannot receive from), its snapshot entry stays :checkpointing, complete-segment-p is never true, and MAIN holds vacuously for that topology.

Each enumerated segment starts with a :checkpoint input and is extended only while the target snapshot is incomplete, so every segment that reaches completion is complete in the sense of complete-segment-p (checked for each one). The model code was checked against ACL2 on 30 random executions per topology.

The first three topologies have complete segments, and in every one of them the reordered run reaches the same final state. This is so even though the snapshot can be misleading there. In "sends without a matching receive", message m1 sits on (1 . 2) forever and is in no recorded channel state. In "duplicate ids", 2 receives every message from 1 twice. MAIN is a statement about reordering inputs, not about the recorded snapshot being a meaningful global state, so these don't contradict it.

In the fourth topology there are no complete segments: MAIN is true, but says nothing. The stronger lemma it is proved from, reorder-from-state, still applies to every legal execution, and the swaps above still commute.

About this page

The model code is a direct port of exp1/solution.lisp (records g/s, local-ps, local-out, head-of, pop-chans, deliver, cl-step, legal-input, recorded-p, segment-target, checkpoint-complete, complete-segment-p, pre-inputs, post-inputs, state-equiv). It was checked against ACL2 8.7 running the certified solution, with the same concrete functions attached via defattach. On 41 executions in the consistent topology (the example and 40 random legal ones), and on 30 random executions in each of the four topologies (with matching in-nbrs, out-nbrs and sys-procs attached), the final state, pre-inputs, post-inputs, complete-segment-p and state-equiv of the reordering all matched. The commuting checks on this page are computed, not assumed. The general proof is reorder-from-state and MAIN in the solution. The message arrows in section 3 are bookkeeping for the picture only and are not part of the model's state.
