# Erlang in ACL2: a continuation-passing style evaluator

An implementation, in ACL2, of the system described in *Erlang in ACL2: A
Continuation-Passing Style Evaluator* (Bora and Greenstreet, ACL2-2026): an
Erlang-to-ACL2 front end, a CPS evaluator for the ASTs, a scheduler that is
a constrained function with an executable attachment, and proofs about
`sum_of_nats` and a parallel `reduce`.

## Translating Erlang to ACL2 (the front end)

To turn the module in a `.erl` file into ACL2 forms:

```
escript /work/erl_to_acl2.erl FILE.erl [OUT.lisp]
```

This writes `OUT.lisp` (by default `FILE.lisp` next to `FILE.erl`), a
certifiable book containing

```lisp
(in-package "ACL2")
(defconst *MODNAME-module* '(:module |MODNAME| EXPORTS IMPORTS FUNCTIONS))
```

where `MODNAME` is the name in the `-module(...)` attribute. To translate
expressions instead:

```
$ escript /work/erl_to_acl2.erl -e "2 + 2."
(:binop + (:integer 2) (:integer 2))
```

From an Erlang shell, `erl_to_acl2:expr_string("2 + 2.")` returns the same text
(compile it first with `erlc erl_to_acl2.erl`).

## Running a function of a loaded module

In ACL2, include the scheduler (which attaches the executable scheduler) and
the generated book, then call `erl-run-function`:

```lisp
(include-book "/work/scheduler")
(include-book "/work/erl/add_pairs")     ; the book written by erl_to_acl2

(erl-run-function (erl-make-world (list *add_pairs-module*))   ; logical world
                  '|add_pairs|                                  ; module
                  '|add_pairs|                                  ; function
                  (list (erl-ints '(1 2 3 4 5 6 7 8)))          ; arguments
                  1000)                                         ; fuel
```

`(erl-run-function WORLD MOD FN ARGS FUEL)` creates process 0 evaluating
`MOD:FN(ARGS...)` and runs the executable scheduler for at most `FUEL`
scheduler steps, giving each process run `FUEL` units of fuel. It returns
the exit value of process 0 if it terminated normally, and otherwise
`(STATUS VALUE)` with `STATUS` one of `:blocked`, `:crashed` (uncaught
exception), `:out-of-fuel` or `:ready`. The scheduler prints the actions it
takes. To get Erlang syntax, wrap the call in `erl-format`:

```lisp
(erl-format (erl-run-function (erl-make-world (list *add_pairs-module*)) '|add_pairs|
                              '|add_pairs| (list (erl-ints '(1 2 3 4 5 6 7 8))) 1000))
; => "[3,7,11,15]"
```

`WORLD` may contain several modules: `(erl-make-world (list *m1-module* *m2-module*))`.
`(erl-run-function-sys ...)` returns the final process table instead, and
`(erl-exit-values SYS)` extracts `(pid status . value)` for every process.
`(erl-eval-call WORLD MOD FN ARGS FUEL)` evaluates a sequential call directly
with `eval-cont-list`, without the scheduler.

Arguments are Erlang values in the representation below; helpers:
`(erl-val-integer 5)` or `(make-erl-val-integer :val 5)`, `(erl-ints '(1 2 3))`
for a list of integers, `(erl-atom '|foo|)`, `(erl-tuple (list v1 v2))`,
`(lisp-to-erl-list (list v1 v2))`, `(erl-pid 3)`, and `'(:funref |erlang| + 2)`
for `fun erlang:'+'/2`.

## Representation

### ASTs (output of the front end)

The ACL2 AST mirrors `erl_parse` with line numbers dropped. As in the paper,
argument lists, tuple elements and clause patterns are normalized from Erlang
lists `[A, B]` to parsed lists `(:cons A (:cons B (:nil)))`, and calls are
tagged as local, remote or fun calls.

```
(:integer I)  (:atom |a|)  (:var |X|)  (:nil)  (:cons H T)  (:tuple ELEMS)
(:binop OP L R)  (:unop OP E)  (:match PAT E)  (:send DEST MSG)     ; DEST ! MSG
(:block BODY)  (:if CLAUSES)  (:case E CLAUSES)  (:receive CLAUSES)
(:try BODY OF-CLAUSES CATCH-CLAUSES AFTER-BODY)  (:catch E)
(:fun CLAUSES)  (:named-fun |Name| CLAUSES)  (:fun-ref |f| ARITY)  (:fun-ref-remote |m| |f| ARITY)
(:call-local |f| ARGS)  (:call-remote |m| |f| ARGS)  (:call-fun FEXPR ARGS)
clause:  (:clause PATS GUARDS BODY)      ; GUARDS: list of guard sequences
module:  (:module |name| ((|f| . ARITY) ...) (((|f| . ARITY) . |mod|) ...) (((|f| . ARITY) . CLAUSES) ...))
```

Operators are ACL2 symbols (`+`, `-`, `*`, `div`, `rem`, `==`, `/=`, `|=:=|`,
`|=/=|`, `<`, `=<`, `andalso`, `++`, ...); strings become lists of integers.
Supported: integers, atoms, tuples, lists, strings, all binary/unary
operators on these, match, `if`, `case`, `try ... of ... catch ... after`,
`catch`, funs, closures and named funs, `fun f/N`, local, remote, imported
and fun calls, `spawn/1`, `self/0`, send and receive, and common BIFs
(`erlang`: type tests, `length`, `hd`, `tl`, `element`, `tuple_size`, `abs`,
`max`, `min`, `throw`, `error`, `exit`, ...; `lists`: `reverse`, `append`,
`split`, `seq`, `sum`, `nth`, `last`, `member`). Not supported: maps, floats,
binaries, list comprehensions, `receive ... after`.

### Values

```
(:integer i) (:atom a) (:nil) (:cons h t) (:tuple (v1 ... vn)) (:pid n)
(:fun clauses env module name) (:funref module name arity)
```

Exceptions are not values: they are signals `(:exception class reason)`
that pass through continuations until a `try`/`catch` handles them.

## The CPS evaluator (Sections 3.2, 3.3)

The **estate** (`make-estate`, `estate->val`, `update-estate->val`, ...) holds
the value produced by the previous continuation, the variable bindings, the
current module, the logical world, the process's own pid, the inbox
(maintained by the scheduler) and the outbox (one queue per destination pid,
which gives Erlang's per-pair ordering guarantee).

A continuation is a tagged list that performs one primitive operation:
`(:expr ast)`, `(:binop1 op right)`, `(:binop2 op left)`, `(:receive clauses)`,
`(:receive2 clauses)`, `(:call-local f)`, `(:restore env module)`, `(:try-of ...)`,
...; the constructors of Figure 4 are available as `cont-expr`, `cont-binop1`,
`cont-binop2`, `cont-receive`, ... `(eval-cont k rest estate)` performs one
continuation and returns `(mv yield klist estate)`.

`(eval-cont-list klist estate fuel)` is admitted in logic mode, with
measure `(nfix fuel)`. Each continuation evaluated uses one unit of fuel:

* when `klist` is empty, the process has terminated and `estate->val` is its
  exit value (or an uncaught exception);
* on `receive`, the evaluator yields to the scheduler, returning the estate
  with val `(:receive KLIST CLAUSES)`; the scheduler resumes the process with
  the continuation list `((:receive2 CLAUSES) . KLIST)`, which takes the
  oldest matching message from the inbox (or yields again);
* `spawn` is a globally visible action, so it also yields (`(:spawn FUN KLIST)`)
  and the scheduler allocates the new pid;
* when fuel runs out, val is `(:out-of-fuel KLIST)`.

Function calls push a `(:restore env module)` continuation unless the next
continuation already is one (tail-call elimination).

## The scheduler (Section 3.1)

The global state is an alist from pids (natural numbers) to processes
`(status klist estate)`. `(sched-actions sys)` lists the non-stuttering
actions available: `(:run p)` for a ready process, or a blocked one with a
matching message in its inbox, and `(:deliver p dest)` for every non-empty
outbox queue. The scheduler is

```lisp
(encapsulate (((erl-scheduler * *) => *))
  (local (defun erl-scheduler (n sys) ...))
  (defthm erl-scheduler-fair
    (implies (consp (sched-actions sys))
             (member-equal (erl-scheduler n sys) (sched-actions sys)))))
(defattach erl-scheduler erl-scheduler-exec)
```

(`n` is the index of the step in the trace). The only constraint is the
fairness condition of the paper: if a non-stuttering action is available,
one is chosen. `erl-scheduler-exec` goes through the processes in order and
takes the first runnable process or pending message, printing each action.
`(sched-step n sys fuel)` performs one step (an unavailable action
stutters); `(erl-run-sched sys n steps fuel)` runs a trace.

## Section 4.1: `sum-of-nats.lisp`

```lisp
(defthm sum-of-nats-correct
  (implies (and (erl-val-integer-p n-ast)                       ; N is an :integer AST
                (natp (erl-val-integer->val n-ast))
                (sum-test-world-p (estate->world s) (estate->module s))
                (natp fuel)
                (<= (sum-of-nats-fuel (erl-val-integer->val n-ast)) fuel))  ; 14 * (1 + N)
           (equal (estate->val
                   (eval-cont-list (list (cont-expr :expr (sum-of-nats-call n-ast))) s fuel))
                  (let ((n (erl-val-integer->val n-ast)))
                    (make-erl-val-integer :val (/ (+ (* n n) n) 2))))))

(defthm sum-of-nats-closed-form
  (implies (natp n) (equal (sum-of-nats n) (/ (+ (* n n) n) 2))))
```

`sum-test-world-p` says only that the current module maps `sum_of_nats/1` to
the clauses produced by the front end. The fuel bound is `14 * (1 + N)`
(the evaluator uses exactly `7 + 14 N` steps). The proof follows the paper:
`eval-sum-of-nats-base-case`, `eval-sum-of-nats-inductive-case` (symbolic
execution of one level of the body up to the recursive call), and
`eval-sum-of-nats-induct`, which shows that the call continuation, followed by
any continuation list K, returns `(make-erl-val-integer :val (sum-of-nats N))`
to K after `4 + 14 N` steps; then `eval-sum-of-nats` and the closed form.
`sum-of-nats-correct-nat` restates the theorem for a natural number `n`.

## Section 4.2: `reduce.lisp`

`wtree-p` recognizes worker trees: node `i` covers the index range
`[i, hi(i))`, its children cover consecutive subranges of `[i+1, hi(i))`,
and the root `0` covers `[0, n)`. `create-wtree` builds a binomial tree.
`(reduce-initial-sys tree n)` creates (before evaluation, with the ACL2
spawn) the workers `0 .. n-1`, worker `i` calling
`reduce(Parent, Children, i)` with the code of Figure 5.

The invariant `reduce-inv` states that each worker is ready, blocked in its
receive, done, or out of fuel, with the correct partial total (the sum of
the indices of its own range up to the next child it waits for); that every
message in an outbox or inbox is `{Pid_c, sum of the indices of c's range}`;
and that a terminated worker's message is not lost while its parent still
waits for it. The required theorems hold for every scheduler satisfying the
constraint (they are proved about the constrained `erl-scheduler`):

* `reduce-invariant-preserved` — the invariant is preserved by running a
  process (`sched-run`), by delivering a message (`sched-deliver`), and so by
  every scheduler step (`sched-step`); `reduce-invariant-trace` extends this
  to whole traces, and `reduce-inv-initial` shows that it holds initially.
* `reduce-no-blocked-worker` — if the invariant holds and no non-stuttering
  action is left, then no worker is blocked (no deadlock). The theorem also
  assumes that no worker has run out of fuel (`no-out-of-fuel-workers`):
  a worker that runs out of fuel never sends its value, so its parent would
  wait forever.
* `reduce-root-value` — if the root (index 0) has terminated, its value is
  `(make-erl-val-integer :val (sum-of-indices n))`, the sum of the indices
  `0 + ... + (n-1)` (`sum-of-indices-closed-form`: `n(n-1)/2`).
  `reduce-root-value-any-trace` combines this with the trace theorem: for
  every fair scheduler, every number of steps and every amount of fuel,
  starting from `reduce-initial-sys`.
