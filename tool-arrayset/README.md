# Arrayset Revisited, in ACL2

An implementation of the system described in D. Hardin, *Arrayset Revisited*
(ACL2-2026): an array-backed set (multiset) written in Restricted
Algorithmic Rust (RAR), translated mechanically to RAC and then to ACL2, with
correctness proofs in ACL2.

```
src/arrayset.rs  --plexi-->  gen/arrayset.cpp  --rac -a-->  gen/arrayset.lisp
   (RAR)                       (RAC)                         (ACL2, certified)
```

## Files

| Path | What it is |
|------|------------|
| `src/arrayset.rs` | The RAR arrayset (Section 5.1, Figures 5 and 6). It is ordinary Rust and compiles with `rustc`; the code between `// RAR begin` and `// RAR end` is the RAR program, and a test driver `main` comes after it. |
| `plexi/` | **Plexi**, the RAR to RAC transpiler, written in Rust with no external crates (`plexi/src/main.rs`). |
| `gen/arrayset.cpp`, `gen/arrayset6.cpp` | RAC generated by plexi, with `ARR_SZ = 1024` (as in the source) and `ARR_SZ = 6` (`-D ARR_SZ=6`). |
| `gen/arrayset.ast.lsp`, `gen/arrayset6.ast.lsp` | The S-expressions produced by the RAC parser. |
| `gen/arrayset.lisp`, `gen/arrayset6.lisp` | ACL2 produced by the RAC translator (`books/projects/rac`). These are certified against `rtl/rel11/lib/rac`. |
| `arrayset-defs.lisp` | Verification-only definitions: `asetp`, `aset-free-to-used-preconditionp`, `aset-used-to-free-preconditionp`, `no-dups-anext`, `aset-used-list`, `aset-free-list`. |
| `arrayset-thms.lisp` | The theorems of Figures 8 and 9, with supporting lemmas. |
| `arrayset6-defs.lisp`, `arrayset6-thms.lisp` | Generated by `build.sh`: the same books for the `ARR_SZ = 6` instance. |
| `examples.lisp` | The Figure 4 example, checked by execution with `assert-event` on the `ARR_SZ = 6` instance. |
| `build.sh` | Builds everything (see below). |
| `cert.acl2`, `gen/cert.acl2` | Certification world: `(include-book "rtl/rel11/lib/rac" :dir :system)`. This is the same world the RAC `rac -a` script uses. |

## Commands

Everything at once (takes a few seconds; generated files are rewritten):

```sh
cd /work
./build.sh          # set JOBS=n for parallel certification; ./build.sh clean removes outputs
```

`build.sh` runs these steps:

```sh
# 1. Build the transpiler (Rust, offline, no dependencies).
(cd plexi && cargo build --release --offline)

# 2. Build the RAC parser from the community books' RAC sources. build/rac
#    mirrors books/projects/rac: bin/{parse,rac}, plus symlinks to lisp/ and include/.
cp -r /opt/acl2/books/projects/rac/src build/rac-src
make -C build/rac-src RAC=/work/build/rac ACL2=$(command -v acl2) all
ln -sfn /opt/acl2/books/projects/rac/lisp    build/rac/lisp
ln -sfn /opt/acl2/books/projects/rac/include build/rac/include

# 3. RAR -> RAC (plexi), then RAC -> ACL2 (the standard RAC driver `rac -a`,
#    which runs the parser and translate-program, then certifies the result).
plexi/target/release/plexi src/arrayset.rs gen/arrayset.cpp
plexi/target/release/plexi src/arrayset.rs gen/arrayset6.cpp -D ARR_SZ=6
(cd gen && ../build/rac/bin/rac -a arrayset.cpp && ../build/rac/bin/rac -a arrayset6.cpp)

# 4. Make the ARR_SZ = 6 copies of the verification books (sed renames the includes).

# 5. Certify all books.
cert.pl gen/arrayset.lisp gen/arrayset6.lisp arrayset-defs.lisp arrayset-thms.lisp \
        arrayset6-defs.lisp arrayset6-thms.lisp examples.lisp
```

The generated files are checked in, so certifying alone needs only
`cert.pl gen/*.lisp *.lisp`.

To compile and run the Rust source natively (it runs its own small test driver):

```sh
rustc -o /tmp/arrayset src/arrayset.rs && /tmp/arrayset
```

## The RAR program

`free_head`, `used_head`, `aset_add`, `aset_del_head` and `aset_del` are as in
Figures 5 and 6 of the paper. `ARR_SZ` is declared as `usize`, because
`uint` is not a Rust type; plexi emits it as a RAC `uint` constant. The
functions the paper does not show are written from its description:

* `aset_init(aset)` makes elements `1 .. ARR_SZ-1` a circular free list with
  tail `free_lst = ARR_SZ-1`, empties the used list (`used_lst = ARR_SZ`), and
  sets `anext[0] = 0`, all `avals` to 0, and `err = 1`.
* `aset_transfer(used_to_free, aset)` moves the head of the source list (used
  if `used_to_free`, otherwise free) to the head of the other list. Both lists
  are circular, the tail being stored in `used_lst`/`free_lst`, and
  `ARR_SZ` means empty. On success it sets `err = 1`. If the source list is
  empty it sets `err = ARR_SZ` and changes nothing else.
* `aset_find_val_from(start, val, aset)` walks the circular list from `start`
  and returns the index `previ` with `avals[anext[previ]] == val`, or `ARR_SZ`
  if no such index exists. Its loop is a RAR `cfor!` loop, bounded by `ARR_SZ`.

C-style `for` loops are written `cfor!(init; test; update; { body })`, with
`cfor!` defined by `macro_rules!` in the same file. Plexi turns it into a
RAC `for` loop, and the RAC translator turns that into a tail-recursive
function (`ASET_FIND_VAL_FROM-LOOP-0`, `ASET_INIT-LOOP-0`).

Plexi maps Rust types to Algorithmic C types: `usize` and `u64` become
`ac_int<64,false>`, `i64` becomes `ac_int<64,true>`, and `[T; N]` becomes
`array<T, N>`. Loop counters become RAC `uint`. As in Figures 7 and 8,
`avals` therefore holds 64-bit patterns, read back with `(si ... 64)`.

`gen/arrayset.lisp` contains the generated `ASET_DEL`, which has the form of
Figure 7. There is one cosmetic difference: Figure 7 shows
`(BITS (AG 'USED_LST ASET) 63 0)` as the first argument of
`ASET_FIND_VAL_FROM`, but the RAC translator in the installed books drops
that no-op cast between two identical unsigned 64-bit types, so it emits
`(AG 'USED_LST ASET)`. `(BITS (SI VAL 64) 63 0)` appears as in the figure.

## The verification

`arrayset-defs.lisp`:

* `(aset-used-list aset)` and `(aset-free-list aset)` follow `anext` from
  `used_head` (respectively `free_head`) to the list's tail
  `used_lst`/`free_lst`, which is included, for at most `ARR_SZ-1` steps. They
  return the list of indices visited.
* `asetp` requires the following. The fields are naturals, with
  `used_lst, free_lst <= ARR_SZ`. Every `anext[i]` with `i < ARR_SZ` is below
  `ARR_SZ`. Each nonempty list closes, meaning it reaches its tail within
  `ARR_SZ-1` steps. And `(append used-list free-list)` has no duplicates, so
  the two lists are disjoint.
* `aset-free-to-used-preconditionp` and `aset-used-to-free-preconditionp`
  follow the Verus `requires` clauses of Figure 10. They require
  `0 < used_lst, free_lst <= ARR_SZ`, `used_lst != free_lst` and
  `anext[0] = 0`, and that the source list is nonempty (its tail is below
  `ARR_SZ`).
* `no-dups-anext` says that `anext[0 .. ARR_SZ-1]` has no duplicates.

`arrayset-thms.lisp` proves the four theorems with exactly the names and
statements of Figures 8 and 9:

* `aset_add-val-at-used_head--thm`
* `aset_del-val-at-free_head--thm`
* `aset_del_head-used-list--thm`: the used list after `aset_del_head` is the
  `cdr` of the used list before it.
* `aset_del_head-free-list--thm`: the free list after `aset_del_head` is the
  `cons` of the old `used_head` onto the old free list.

The proofs disable `ARR_SZ` and its executable counterpart and use only
`1 < ARR_SZ < 2^32`. So they hold for arbitrary-sized backing arrays, and the
same books certify for both `ARR_SZ = 1024` and `ARR_SZ = 6`. No
`skip-proofs`, `defaxiom` or trust tags are used.

`examples.lisp` checks the Figure 4 example by execution with `ARR_SZ = 6`:
`(aset_del 22 fig4a)` equals the panel (b) state.

* Panel (a): `anext = 0 2 1 4 5 3`, `used_lst = 1`, `free_lst = 5`, contents
  `{33, 22}`.
* Panel (b): `anext = 0 3 2 4 5 1`, `used_lst = 2`, `free_lst = 5`.
* The traversals described in the text are checked too. In panel (b) the free
  list is 5 → 1 → 3 → 4 → 5. The text gives this traversal while describing
  panel (a), but it matches panel (b).
* Panel (a) is reachable: `aset_init`, then `aset_add 22`, then
  `aset_add 33` produces it.
* The hypotheses of all four theorems hold of the panel (a) state.
